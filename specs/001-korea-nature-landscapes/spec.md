# Feature Specification: 한국의 결 (Landscapes of Korea)

**Feature Branch**: `001-korea-nature-landscapes`

**Created**: 2026-09-09

**Status**: Draft

**Input**: User description: "'한국의 결'이라는 제목의 단일 페이지 문화관광 웹사이트를 만든다. 한국의 아름다운 자연 풍경(설악산, 제주, 순천만, 보성 녹차밭)을 큰 사진과 충분한 한국어 소개 글, 부드러운 연속 스크롤 경험으로 보여주는 편집형 문화관광 웹사이트. Hero → 4개 장소 섹션 → 마지막 CTA/footer 순서의 단일 페이지. 각 장소는 이름/영문명, 한 줄 제목, 서로 다른 길이의 본문 2개 문단, 키워드 2~3개, 전체 화면에 가까운 대표 사진을 갖는다. 데스크톱은 이미지가 서서히 확대되며 교차하는 연속 스크롤 연출, 모바일은 단순한 세로 흐름으로 폴백한다. 지정된 실제 문구를 그대로 사용하고, Wikimedia Commons/Unsplash/Pexels 등에서 출처가 명확한 실제 사진을 직접 검색해 다운로드하며 CREDITS.md에 출처를 기록한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 스크롤로 네 장소의 풍경과 글을 순서대로 감상하기 (Priority: P1)

한국 여행에 관심 있는 방문자가 페이지에 들어와 Hero를 보고, 아래로 스크롤하며 설악산 → 제주 → 순천만 → 보성 녹차밭 순서로 각 장소의 대표 사진과 소개 글을 차례로 읽고, 마지막 CTA에 도달한다.

**Why this priority**: 이것이 사이트의 핵심 목적(편집형 문화관광 소개)이자 전체 페이지의 유일한 콘텐츠 흐름이다. 이 흐름이 동작하지 않으면 사이트 자체가 성립하지 않는다.

**Independent Test**: 페이지를 열고 처음부터 끝까지 스크롤하는 것만으로 완전히 검증 가능하다 — Hero 리드문, 네 장소의 이름/한 줄 제목/본문 2문단/키워드/사진이 모두 순서대로 노출되고, 마지막 CTA와 footer로 끝나면 성공.

**Acceptance Scenarios**:

1. **Given** 사용자가 페이지 최상단(Hero)에 있음, **When** 아래로 스크롤함, **Then** 화면이 설악산 섹션으로 자연스럽게 전환되며 장소 이름, 한 줄 제목, 본문 2개 문단, 키워드, 대표 사진이 모두 나타난다.
2. **Given** 사용자가 한 장소 섹션 안에 있음, **When** 스크롤을 멈춤, **Then** 본문이 사라지지 않고 읽을 수 있는 상태로 유지된다.
3. **Given** 사용자가 보성 녹차밭 섹션을 지남, **When** 계속 스크롤함, **Then** 마지막 CTA(제목·문장·버튼)와 footer가 나타나고 페이지가 끝난다.
4. **Given** 사용자가 마지막 CTA에 있음, **When** "처음 풍경부터 다시 보기" 버튼을 클릭함, **Then** 페이지 최상단(Hero)으로 이동한다.

### User Story 2 - 데스크톱에서 장면이 이어지는 몰입형 스크롤 전환 경험하기 (Priority: P2)

데스크톱 사용자가 스크롤할 때 다음 장소의 이미지가 서서히 확대되며 앞으로 들어오고, 이전/다음 이미지가 짧게 겹친 뒤 교차하며, 장소 이름·한 줄 제목·본문이 약간의 시차를 두고 순서대로 나타나는 연속적인 장면 전환을 경험한다.

**Why this priority**: 이 전환 연출이 사이트의 차별화된 편집 감각(여행 잡지 같은 리듬)을 만들지만, 이것이 없어도(단순 페이드/즉시 표시로 대체되어도) User Story 1의 핵심 콘텐츠 전달은 여전히 성립한다.

**Independent Test**: 데스크톱 너비의 브라우저에서 마우스 휠로 천천히 스크롤하며, 섹션 사이 전환이 한 번의 휠 동작으로 통째로 바뀌지 않고 이미지 확대/교차와 텍스트의 순차 등장이 관찰되면 성공.

**Acceptance Scenarios**:

1. **Given** 데스크톱 사용자가 한 장소 섹션에서 다음 장소로 넘어가는 구간에 있음, **When** 스크롤함, **Then** 다음 장소의 이미지가 점진적으로 확대되며 화면에 들어오고 이전 이미지와 잠시 겹쳐 보인다.
2. **Given** 다음 장소 섹션에 진입함, **When** 텍스트가 나타남, **Then** 장소 이름 → 한 줄 제목 → 본문 순서로 약간의 시차를 두고 순차적으로 나타난다.
3. **Given** 사용자가 한 번의 휠 스크롤 동작을 수행함, **When** 스크롤 위치를 확인함, **Then** 장면이 통째로 다음 섹션으로 강제 점프하지 않고 스크롤 입력량에 비례해 연속적으로 이동한다.
4. **Given** 사용자가 한 섹션을 완전히 지나침, **When** 스크롤을 계속함, **Then** 스크롤이 특정 섹션에 멈춰 다시 풀리기를 기다리는 지점이 없다(핀 고정/재입력 대기 없음).

### User Story 3 - 모바일에서 읽기 쉬운 세로 흐름으로 콘텐츠 확인하기 (Priority: P2)

모바일 사용자가 페이지를 방문해, 데스크톱의 복잡한 장면 전환 대신 일반적인 세로 스크롤로 Hero와 네 장소의 전체 콘텐츠(이름, 한 줄 제목, 본문 2문단 전체, 키워드, 사진)를 빠짐없이 읽는다.

**Why this priority**: 모바일 트래픽은 실사용에서 큰 비중을 차지하며, 콘텐츠가 숨겨지거나 축약되면 헌법 원칙(본문을 캡션으로 축소하지 않음)과 기능 요구를 모두 위반하게 된다. 다만 이는 User Story 1의 콘텐츠가 이미 존재한다는 전제 위에 동작하는 표시 방식의 변형이므로 P2로 분류한다.

**Independent Test**: 모바일 폭(예: 375px) 뷰포트에서 페이지를 처음부터 끝까지 스크롤하며, 모든 장소의 본문 2문단이 축약 없이 전부 표시되고 전환이 단순한(급격한 확대/교차 없는) 세로 흐름임을 확인하면 성공.

**Acceptance Scenarios**:

1. **Given** 모바일 뷰포트에서 페이지를 열람함, **When** 각 장소 섹션에 도달함, **Then** 본문 2개 문단 전체가 숨김이나 생략 없이 표시된다.
2. **Given** 모바일 뷰포트임, **When** 섹션 간 스크롤함, **Then** 데스크톱의 확대/교차 연출 대신 단순한 전환(예: 순차적 등장)으로 전환된다.
3. **Given** 모바일 사용자가 스크롤함, **When** 어떤 시점에서도, **Then** CSS scroll-snap이나 강제 스크롤 이동으로 인해 스크롤 위치가 사용자 의도와 다르게 튀지 않는다.

---

### User Story 4 - 움직임에 민감한 사용자가 축소된 모션으로 콘텐츠 확인하기 (Priority: P3)

시스템 설정에서 "동작 줄이기(prefers-reduced-motion)"를 활성화한 사용자가 페이지를 방문했을 때, 과도한 확대·교차·시차 애니메이션 없이도 모든 텍스트와 사진을 문제없이 읽고 볼 수 있다.

**Why this priority**: 접근성 요구사항이며 헌법 원칙에 명시되어 있으나, 영향을 받는 사용자 집단이 상대적으로 작아 핵심 콘텐츠 흐름(P1)과 주요 전환 경험(P2) 이후에 검증해도 무방하다.

**Independent Test**: 운영체제/브라우저의 동작 줄이기 설정을 켠 상태에서 페이지를 스크롤하며, 확대·교차·시차 애니메이션이 최소화되거나 제거된 채로 모든 콘텐츠가 즉시 읽을 수 있는 상태로 나타나면 성공.

**Acceptance Scenarios**:

1. **Given** 사용자의 시스템이 동작 줄이기를 요청함, **When** 페이지를 스크롤함, **Then** 이미지 확대·교차 및 텍스트 시차 등장 효과가 제거되거나 크게 축소된 상태로 콘텐츠가 표시된다.
2. **Given** 동작 줄이기가 활성화됨, **When** 어떤 섹션에 있어도, **Then** 모든 텍스트와 이미지가 완전한 상태로 즉시 접근 가능하다.

### Edge Cases

- 실제 사진 검색/다운로드에 실패해 특정 장소의 대표 사진을 확보하지 못한 경우, 해당 장소를 placeholder 이미지로 채우지 않고 어떤 장소의 사진이 누락되었는지 명확히 알리며 구현을 완료 상태로 간주하지 않는다.
- 매우 작은 화면(예: 320px 폭)이나 매우 큰 화면(예: 초광폭 데스크톱 모니터)에서도 본문 폭 제한과 이미지 비율이 레이아웃을 깨뜨리지 않아야 한다.
- 키보드만으로 탐색하는 사용자가 "처음 풍경부터 다시 보기" 등 상호작용 요소에 접근하고 실행할 수 있어야 한다.
- 스크롤 휠이 아닌 터치패드, 터치스크린 스와이프, 스크롤바 드래그, 키보드 Page Down 등 다른 입력 방식으로도 동일한 연속 스크롤 흐름이 성립해야 한다.
- 이미지 로딩이 느린 네트워크 환경에서도 본문 텍스트는 이미지 로딩 여부와 무관하게 읽을 수 있어야 한다.
- 브라우저 창 크기를 데스크톱과 모바일 임계값 사이에서 조절할 때, 두 전환 방식(연속 스크롤 연출 ↔ 단순 세로 흐름) 사이의 전환이 콘텐츠 손실이나 레이아웃 깨짐 없이 이루어져야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 페이지는 단 하나의 HTML 문서로 구성되며, Hero → 설악산 → 제주 → 순천만 → 보성 녹차밭 → 마지막 CTA/footer 순서를 정확히 유지해야 한다.
- **FR-002**: Hero 섹션은 제목("한국의 결"), 영문 표기("LANDSCAPES OF KOREA"), 그리고 페이지의 관점을 설명하는 리드문을 지정된 문구 그대로 포함해야 한다.
- **FR-003**: 각 장소 섹션(설악산, 제주, 순천만, 보성 녹차밭)은 다음을 모두 포함해야 한다 — 장소의 한글 이름과 영문 이름, 풍경의 성격을 짚는 한 줄 제목, 서로 다른 길이의 소개 본문 2개 문단(지정된 문구 그대로, 축약 없이), 2~3개의 짧은 키워드, 전체 화면에 가까운 대표 사진.
- **FR-004**: 각 장소의 본문 2개 문단은 지정된 실제 한국어 문구를 그대로 사용해야 하며, 요약하거나 한 문장짜리 캡션으로 축약해서는 안 된다.
- **FR-005**: 데스크톱 레이아웃에서 본문 영역의 폭은 약 36~48rem으로 제한되고, 충분한 행간을 가지며, 이미지와 나란히 배치되거나 반투명한 읽기 패널 위에 배치되어야 한다.
- **FR-006**: 네 장소 섹션은 이미지와 본문의 좌우 배치, 여백, 정렬이 서로 달라야 하며, 모든 장소가 동일한 이미지·텍스트 배치를 반복해서는 안 된다.
- **FR-007**: 본문 텍스트는 스크롤 중 완전히 나타난 뒤 최소 2초 이상 읽을 수 있는 상태로 유지되어야 하며(스크롤을 멈추지 않아도, 정상 속도로 스크롤하는 사용자 기준 최소 2초의 노출 구간을 확보해야 함), 나타나자마자 사라지는 방식으로 구현되어서는 안 된다.
- **FR-008**: 데스크톱 스크롤 경험은 다음 장소의 이미지가 서서히 확대되며 들어오고, 이전 이미지와 짧게 겹친 뒤 교차하며, 장소 이름·한 줄 제목·본문이 순차적인 시차를 두고 등장하는 연속적 전환으로 구현되어야 한다.
- **FR-009**: 스크롤 전환은 섹션마다 개별적으로 멈췄다 풀리는 핀(pin) 방식, CSS scroll-snap, 휠 이벤트 가로채기, 강제 스크롤 이동, 또는 한 번의 휠 동작으로 장면 전체가 교체되는 방식을 사용해서는 안 되며, 스크롤 입력량에 비례한 연속적 흐름으로 구현되어야 한다.
- **FR-010**: 모바일 레이아웃에서는 데스크톱의 복잡한 확대/교차 전환 대신 일반적인 세로 스크롤 흐름과 단순한 전환을 사용해야 하며, 이때도 본문 2개 문단은 축약되거나 숨겨지지 않고 전체가 표시되어야 한다.
- **FR-011**: 페이지는 시맨틱 HTML 요소를 사용하고, 모든 상호작용 요소(예: CTA 버튼)는 키보드만으로 접근하고 실행할 수 있어야 한다.
- **FR-012**: 시스템이 동작 줄이기(prefers-reduced-motion)를 요청하는 경우, 확대·교차·시차 애니메이션은 제거되거나 크게 축소되어야 하며, 모든 콘텐츠는 애니메이션 없이도 완전히 읽고 볼 수 있어야 한다.
- **FR-013**: 마지막 섹션은 지정된 CTA 제목("오래 보고 싶은 풍경은 천천히 남습니다"), 문장, "처음 풍경부터 다시 보기" 버튼, 그리고 간단한 footer를 지정된 문구 그대로 포함해야 한다. 버튼을 실행하면 페이지 최상단(Hero)으로 이동해야 한다.
- **FR-014**: 모든 페이지 경로와 이미지 경로는 상대 경로로 작성되어 하위 경로(subpath)에 배포되어도 정상 동작해야 한다.
- **FR-015**: 각 장소 및 Hero의 대표 사진은 재사용 조건을 확인할 수 있는 출처(예: Wikimedia Commons, Unsplash, Pexels 등 원문 상세 페이지에서 라이선스와 작가를 확인 가능한 출처)에서 직접 검색되어 프로젝트 내부 이미지 폴더에 다운로드된 실제 사진이어야 하며, 외부 URL 핫링크나 출처가 불분명한 이미지, 단색/placeholder 이미지를 사용해서는 안 된다. 선택하는 사진은 상업적 이용과 변형(리사이즈, 크롭, 포맷 변환 등)을 모두 명시적으로 허용하는 라이선스(예: CC0, CC-BY, CC-BY-SA)여야 하며, 변형이나 상업적 이용을 금지하는 편집적/제한적 라이선스 사진은 사용해서는 안 된다.
- **FR-016**: 사용된 모든 이미지 파일에 대해 프로젝트 내 파일 경로, 촬영자/제공 기관, 원본 상세 페이지 URL, 라이선스/사용 조건, 확인 날짜를 기록한 CREDITS.md가 프로젝트 루트에 존재해야 한다.
- **FR-017**: 모든 이미지는 풍경을 구체적으로 설명하는 한국어 alt 텍스트를 가져야 한다.
- **FR-018**: 특정 장소의 실제 대표 사진을 확보하지 못한 경우, 해당 사실이 명확히 보고되어야 하며 해당 장소를 placeholder로 채운 상태를 완료된 결과물로 제시해서는 안 된다.

### Key Entities

- **장소(Place)**: 페이지에 소개되는 자연 명소 하나(설악산/제주/순천만/보성 녹차밭). 한글 이름, 영문 이름, 한 줄 제목, 본문 2개 문단, 키워드 목록(2~3개), 대표 사진 1장, 그리고 해당 사진의 출처 정보를 속성으로 가진다.
- **Hero 콘텐츠**: 페이지 최상단에 표시되는 도입부. 제목, 영문 표기, 리드문, 배경/대표 사진 1장을 속성으로 가진다.
- **마지막 CTA**: 페이지 종료부 콘텐츠. 제목, 안내 문장, 재시작 버튼(라벨과 최상단 이동 동작)을 속성으로 가진다.
- **이미지 출처 기록(Credit)**: CREDITS.md에 기록되는 각 이미지에 대한 항목. 프로젝트 내 파일 경로, 촬영자/제공 기관, 원본 URL, 라이선스, 확인 날짜를 속성으로 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 방문자가 페이지를 처음부터 끝까지 한 번의 연속된 스크롤 동작만으로 Hero부터 마지막 CTA까지 도달할 수 있다(별도의 클릭이나 페이지 이동 없이).
- **SC-002**: 네 장소 각각에 대해 지정된 본문 2개 문단 전체가 100% 축약 없이 화면에 노출된다(데스크톱과 모바일 모두).
- **SC-003** *(post-launch business metric, not pre-ship buildable coverage — see Assumptions)*: 임의로 선택한 사용자 100명 중 스크롤 전환이 "부자연스럽게 끊긴다" 또는 "강제로 튄다"고 응답하는 비율이 10% 미만이다. 출시 전 검증은 이 지표 대신 FR-009의 객관적 규칙(핀 분리 없음, scroll-snap 없음, 휠 가로채기 없음, 입력량 비례 이동)을 리뷰어가 직접 확인하는 것으로 대체한다.
- **SC-004**: 사용된 4개 이상의 실제 장소 사진 전부가 CREDITS.md에 출처·작가·원본 URL·라이선스·확인 날짜와 함께 100% 기록되어 있다.
- **SC-005**: 동작 줄이기를 활성화한 상태에서도 사용자는 애니메이션 관련 방해 없이 모든 텍스트와 이미지를 100% 확인할 수 있다.
- **SC-006**: 페이지를 GitHub Pages와 같은 하위 경로 환경에 배포했을 때 모든 이미지와 링크가 깨짐 없이 100% 정상 로드된다.
- **SC-007**: 모바일 뷰포트 사용자가 별도의 조작 없이 세로 스크롤만으로 전체 콘텐츠(4개 장소 + Hero + CTA)를 빠짐없이 확인할 수 있다.

## Assumptions

- 사이트는 한국어를 주 언어로 하되, 각 장소의 영문 표기(SEORAKSAN 등)를 병기하는 것으로 다국어 지원 범위를 한정한다. 전체 UI 문구의 영어 번역본 제공은 이번 범위에 포함하지 않는다.
- "데스크톱"과 "모바일" 레이아웃을 가르는 기준은 뷰포트 폭 768px을 임계값으로 하며(768px 미만: 모바일 단순 세로 흐름, 768px 이상: 데스크톱 연속 스크롤 연출), 별도의 디바이스/입력방식 감지 없이 화면 폭만으로 판단한다.
- 이미지 최적화(WebP 변환, 해상도 축소 등)는 라이선스 조건이 허용하는 범위 내에서 수행하며, 원본 저작물의 실질적 내용이나 화질 인상을 훼손하지 않는 선에서 진행한다.
- 사진 검색은 웹 검색/브라우징이 가능한 환경을 전제로 하며, 필요한 네트워크 접근 승인은 구현 단계에서 별도로 요청한다.
- CTA의 "처음 풍경부터 다시 보기" 버튼은 별도 페이지 이동 없이 동일 페이지 내 최상단으로 스크롤 이동하는 것으로 해석한다.
- 프로젝트 루트의 DESIGN.md에 정의된 시각적 스타일(색상, 타이포그래피 등)을 이 기능의 실제 비주얼 구현 기준으로 삼으며, 본 스펙에서는 그 시각 규칙 자체를 재정의하지 않는다.
- SC-003은 실제 사용자 100명을 대상으로 한 설문을 전제로 하는 출시 후 비즈니스 지표이며, 이 기능의 구현 완료 여부를 가르는 사전 빌드 검증 항목으로는 다루지 않는다. 사전 검증은 FR-009에 명시된 객관적 규칙(섹션별 개별 pin 금지, CSS scroll-snap 금지, 휠 이벤트 가로채기/강제 스크롤 금지, 스크롤 입력량에 비례한 이동)을 리뷰어가 직접 확인하는 것으로 대체한다.
